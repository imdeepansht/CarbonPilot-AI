Data flows one direction, stage by stage

Each stage is built and tested independently, then chained into a single hourly cycle from raw feeds to a downloadable report.

1

External feeds

Live or forecast weather, grid carbon intensity, and data-centre load.

2

Forecasting

Load and solar-availability models project the next 24–48 hours.

3

Optimisation

An hourly source plan and its carbon/water footprint are computed together.

4

Reporting

The dashboard shows the plan, savings, and a downloadable ESG summary.

Five models, one pipeline

Every box below is a real function in the backend — a lightweight, swappable stand-in for the heavier model named in our research where build time didn't allow for it.

Load forecasting

Predicts hourly power demand 24–48h ahead.

  • Fourier-feature regression over daily & weekly cycles
  • Trained on a labelled synthetic load profile
  • Swappable for Prophet, SARIMA, or an LSTM later

Solar forecasting

Estimates expected solar output for the same window.

  • Regression on cloud cover & irradiance
  • Live weather via Open-Meteo, no API key
  • Falls back to a clear-sky model offline

Source optimisation

Chooses grid, solar, battery, or diesel per hour.

  • Linear program across the whole horizon (PuLP / CBC)
  • Couples every hour through battery state of charge
  • Cost ↔ carbon priority is a tunable shadow price

Carbon & water calculator

Converts the source plan into footprint figures.

  • Published IPCC / CEA emission factors
  • Industry WUE benchmark for cooling water
  • Compared against an all-grid baseline

ESG narrative generator

Turns the figures into a plain-language summary.

  • Structured prompt to Claude
  • Grounded in the run's own computed numbers
  • Template fallback if no API key is set

Hourly scheduler

Re-runs the full cycle automatically.

  • APScheduler background job
  • Re-forecasts on a fixed interval
  • Every run is kept in a local run history

Sensors, one per industry domain
